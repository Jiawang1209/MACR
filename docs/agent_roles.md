# Agent 角色定义 (Agent Role Definitions)

> 消息格式见 [message_protocol.md](message_protocol.md)。

## 角色列表 (Role Definitions)

### Supervisor / Orchestrator

**职责**：接收、判断、拆解任务；决定调用哪些 Agent；控制执行顺序；维护全局状态；触发审查/返工/人工审核；生成最终输出。

**边界**：不负责专业判断，只负责流程控制与协同调度。

**权限**：读写 Blackboard、路由消息。

**消息类型**：产出 `task`、`decision`；消费全部类型。

---

### Planner

**职责**：生成初步方案；拆解任务步骤；判断所需工具与数据；给出执行路线；标记潜在风险。

**边界**：不执行任务，不评判是否合格。

**权限**：读 Blackboard。

**消息类型**：产出 `proposal`、`plan`。

---

### Executor / Implementer

**职责**：按明确方案执行任务；生成代码/分析/报告/图表；记录执行过程；输出证据（改动文件、工具调用、测试结果）。

**边界**：只能基于 approved plan 执行；不决定是否合格。

**权限**：工具调用、写产物。

**消息类型**：产出 `result`、`revision_result`。

---

### Reviewer

**职责**：审查 Planner 方案与 Executor 结果；检查逻辑错误、是否偏离目标、是否缺少证据；给出修改建议。

**边界**：不重新执行任务；默认不能修改代码。

**权限**：只读。

**消息类型**：产出 `review`、`critique`、`revision_request`。

---

### Evaluator

**职责**：依据规则、证据、测试结果与评价指标判断输出是否合格；判断是否需要返工、是否需要人工审核；输出 PASS / NEEDS_FIX / BLOCKED。

**边界**：不执行任务。

**权限**：只读 + 规则库。

**消息类型**：产出 `evaluation`、`decision`。

---

### Tester

**职责**：运行测试；设计测试用例；验证边界条件；检查结果可复现性；输出测试日志。

**边界**：不评判最终是否合格（交由 Evaluator）。

**权限**：运行测试工具。

**消息类型**：产出 `test_report`。

---

### Human Gate

**职责**：对关键决策进行最终确认；接收系统输出；修改/批准/驳回结果；将人工反馈写回系统；作为最终责任主体。

**边界**：非自动化角色。

**权限**：最高（批准、驳回、合并、对外发布）。

**消息类型**：产出 `human_feedback`。

---

## 角色定义风格原则

角色定义的质量直接影响 Agent 的行为边界与协作效果。以下对比模糊与精确两种定义风格：

**反例（模糊角色）**：`你是一个优秀的全栈专家。`

**正例（精确角色）**：`你是代码审查智能体。你只能审查 git diff，不要修改代码。每个问题必须包含文件路径、风险等级、原因和建议。`

**规则**：每个 Agent 必须有明确边界与最小权限（权限最小化）。
